# SudokuV2: функциональный контракт

Обновлено 2026-10-11. Django/Channels/Redis владеют игровым состоянием;
vanilla JS отображает его. Старое приложение `game` предоставляет модели задач.
Название — SudokuV2, пакет — `sudoku_v2`, рабочая ветка — `codex/sudoku-v2`.

## Вход и состояние комнаты

`GET/POST /sudoku-v2/` — имя и комната, `/sudoku-v2/lobby` — игра,
`/ws/sudoku-v2/` — WebSocket. Сессия содержит `sudoku_v2_username` и
`sudoku_v2_room`; старые имена сессии/cookie не используются. Unicode допускается,
имя уникально среди активных игроков комнаты. Bootstrap передаётся через
`json_script`. Cookie используют настройки проекта; локальный DEBUG работает по HTTP.

Presence lease живёт90s, продлевается каждые30s и перед запросом. Записи защищены
случайным connection_id. Последний уход очищает комнату; новый вход создаёт
roomEpoch. Старые пакеты и привязки Twitch не переходят в новое поколение комнаты.
Коды закрытия:4401 — нужен вход;4409 — имя занято/подключение заменено (переход
на форму без повторных попыток);1011 — ошибка проверки presence.

## Доски, управление и панели

- Размеры9×9 и16×16, значения1…N, пустота `''`, канонические индексы0…N²−1.
  Блок имеет сторону `isqrt(N)`; сервер проверяет размер/индекс/значение.
- Ввод кликом и клавиатурой. На16×16 A…G вводят10…16, 0/Delete/Backspace стирают.
  Стрелки учитывают отображаемые перестановки. В полях меню игровые клавиши выключены.
- Исходные клетки и завершённые доски неизменяемы. Неверная полная доска остаётся
  доступной; для исправления при исчерпанном лимите сначала стереть цифру.
  Значение нельзя использовать больше N раз, включая исходные/ошибочные клетки.
- «Сначала цифра» фиксирует выбранное значение до повторного выбора/новой доски,
  выключения режима или исчерпания лимита. Фокус/стрелки сами не пишут значение.
- Заметки — локальные кандидаты, разделённые по комнате, имени и generationId.
  Сетка кандидатов3×3/4×4. Режим заметок также соблюдает лимит значений.
- Ошибки определяет сервер по приватному решению. Таймер использует startedAt,
  serverNow и единожды установленный finishedAt. После завершения можно создать новую доску.
- Своя доска, управление и соперники — три панели GridStack14.0.0 (локальный vendor
  с MIT LICENSE). Перемещение только за ручку, изменение размера — за угол.
  Включены при `(min-width:900px) and (pointer:fine)`, раскладка хранится лишь в
  памяти страницы; reload/reset возвращают исходную. На телефоне и coarse-pointer
  фиксированный порядок: доска → управление → соперники. Пустая панель соперников скрыта.
- Справа одна выбранная доска; вкладки всех присутствующих показывают имя,
  заполненность, время, бонусные клетки и активные эффекты. Смена/уход участника
  не пересоздаёт DOM собственной доски. На9/16 нет горизонтального скролла страницы.

Ход отображается немедленно, следующие ходы не блокируются ожиданием ответа.
Позднее подтверждение не стирает более свежий ввод. Offline-ввод остаётся в памяти
и **не переотправляется**: reconnect получает серверный снимок. После10s без игрового
ответа соединение восстанавливается; задержки reconnect ограничены15s. Twitch имеет
собственные requestId/таймеры и не подтверждает игровые ходы.

## Генерация и сложность

UI выбирает готовую задачу из `game.SudokuBoard` по сложности и количеству клеток.
`for_size()` отделяет9 от16; старый game по умолчанию выбирает9. Миграций схемы нет.
Новая генерация атомарно сохраняет доску и размер контекста, выдаёт generationId,
очищает эффекты и потреблённые бонусы. Смена размера в форме относится к следующей
генерации, ввод использует размер текущей доски.

`game/generator.py` создаёт полное решение из перемешанного латинского шаблона,
удаляет подсказки с проверкой единственности. Solver использует битовые маски,
MRV и hidden singles, останавливая подсчёт после второго решения. Ограничены время
и число попыток. Для высокой доли пустых клеток удаление идёт полосами по строкам/
столбцам; единственность проверяется после каждого удаления.

| Размер | Лёгкая | Средняя | Сложная |
| --- | --- | --- | --- |
|9×9|1…30 пустых|31…55|56…81|
|16×16|1…94 пустых|95…173|174…256|

Это диапазоны числа пустых клеток, **не оценка сложности человеческого решения**.
Верхняя граница не обещает достижимость: пустая доска не имеет единственного
решения. При превышении бюджета команда завершится с понятной ошибкой,
не сохраняя непроверенную задачу. Квота проверяет также ранее сохранённые задачи:
полноту/валидность решения, диапазон и единственность; испорченные не засчитываются.

```powershell
.venv\Scripts\python.exe manage.py fillSudoku --sizes 9 16 --minimum 10 --max-seconds 30 --settings=sudoku_v2.worker_settings
```

`--minimum` применяется отдельно к каждой паре размер/сложность, `--seed` делает
генерацию воспроизводимой в пределах времени выполнения. Worker settings убирают
старые startup hooks очистки комнат; для production наполнения указывать их явно.

## Серверные бонусы

Первое **правильное** заполнение бонусной клетки потребляет её один раз на поколение.
Тип выбирается при генерации доски, случайные параметры эффекта — сервером при
активации. Цели — текущие незавершившие оппоненты со сгенерированными досками.
Если целей нет, бонус потреблён, но эффект пропущен. Значок остаётся до новой доски.

- SWAP меняет две строки/столбца внутри одной группы B=`isqrt(N)`.
  Меняются rowOrder/columnOrder, а решение, values и индексы остаются каноническими.
  Перестановка сохраняется до перегенерации.
- SHADOW_BOX — размытие блока; ROLL — вращение; DANCE — движение;
  GRAYSCALE — обесцвечивание; PULSE — пульсация прозрачности.
- Временный эффект содержит id, kind, params, startsAt, expiresAt. Длительность
  задаётся `SUDOKU_V2_EFFECT_DURATION_MS`, default30000; интенсивность —
  серверными `EFFECT_DEFAULTS` в constants.py. Параметры чата их не меняют.
- Параметры события одинаковы для всех целей, включая смешанные9/16. Для SWAP
  используется пересечение допустимых пар всех размеров, для блока — общий диапазон.
- Каждый экземпляр имеет свой вложенный визуальный слой и setTimeout. Повторы
  одного типа независимы; повтор доставки того же id не перезапускает эффект.
  Reload/reconnect восстанавливает оставшееся время, visibilitychange сверяет
  истечение, новое поколение очищает свои таймеры. Доступ к клеткам сохраняется.

Ход источника, потребление и все цели фиксируются одной Redis-транзакцией
WATCH/MULTI с проверкой presence, поколений и ревизий. Рассылка — после commit;
при сбое доставки снимок остаётся источником истины. Exactly-once доставки WS нет.

## Контекст и оформление

SudokuConfig разделяет серверные preferences, runtime и local-context.
Preferences: размер/сложность следующей доски, заметки/ошибки/«сначала цифра»,
набор символов, выбранный соперник, twitchChannel и twitchCooldown. Переданные
из браузера username/room не определяют владение. `set_context` содержит generationId:
позднее сохранение настроек старой доски получает stale_context, затем клиент
обновляет снимок и повторяет только несохранённые preferences.

Оформление: цифры, два встроенных SVG-набора16 символов и пользовательская
вертикальная полоса квадратных плиток. Недостающие символы белые; лишние допустимы.
Пользовательский Blob хранится в IndexedDB, заметки — в localStorage. Они не уходят
на сервер; отказ хранилища оставляет работу в памяти и показывает сообщение.
Клетки, заметки и изображения сохраняют DOM при обычном ходе/перестановке.

## WebSocket и приватность

Конверт — `{kind,data}`. Публичная доска: name, generationId, revision, size,
difficulty, values, fixedCells, bonuses, wrongCells, startedAt, finishedAt,
completed, requiresGeneration, rowOrder, columnOrder, consumedBonusCells,
activeEffects. Полное решение и чужие preferences в рассылки не входят.

| Запрос/событие | Назначение |
| --- | --- |
| get_board_data → board_data | Своя доска, все публичные boards, свой config, catalog, serverNow |
| set_value → set_value | boardName, generationId, cellIndex, value; подтверждение и публичная доска |
| generate_board → board_data | difficulty/size → новое поколение |
| set_context → context_data | Только свой нормализованный config |
| participants_data | Актуальный состав комнаты, не подтверждение хода |
| bonus_applied | eventId/source/kind/params/targets/serverNow; targets — дельта, не весь roster |
| connect_twitch / disconnect_twitch / get_twitch_status → twitch_status | Отдельные requestId, bindings, workerStatus, serverNow |
| error | code/message/requestKind для обработанного запроса; для Twitch также requestId |

Catalog: sizes=[9,16], difficulties, bonuses и symbolPresets. Клиент игнорирует
меньшие ревизии и доски ушедших; полный reconnect-снимок сбрасывает старый roster.
Локальные optimistic edits не удаляются бонусными/статусными уведомлениями.
Ошибка сохранения настроек не подтверждает игровой ход; `board_busy` повторяет
сохранение актуальных preferences через250ms. Первичная поправка серверного времени
может быть отрицательной; поздние снимки не сдвигают часы эффектов назад.

Redis: `sudoku-v2:<encoded-room>` для игры, `sudoku-v2-global:twitch` для реестра.
На доску — values/fixed/metadata/solution hashes; roomEpoch отделяет жизненные циклы.
Общие guards обеспечивают CAS, а Twitch дополнительно защищён bindingId,
worker lease, message-id и cooldown. Namespaces не пересекаются даже с комнатой twitch.

## Twitch

Один общий read-only IRC-бот работает отдельной management command того же проекта;
игрового WebSocket/суперпользователя/доски у него нет. Сайт хранит desired bindings,
worker сверяет их каждые2s. Channel связан с лобби и зарегистрировавшим игроком;
только он меняет КД или отключает связь. Повтор connect меняет только КД,
сохраняя lastAppliedAt и bindingId. КД0…86400, default0, расходуется успешным эффектом.
Без owner команды пропускаются, но связь остаётся до очистки комнаты/disconnect.

Команды `!command name args`: swap, blur/shadow, rotate/roll, dance, gray, pulse.
Default name=`*` — оппоненты owner. Недопустимое имя/параметр получает default;
имена с пробелами — в двойных кавычках, апострофы и backslash буквальные.
Номера с1; длительность/интенсивность — только серверные. Message-id дедуплицируется
24h атомарно с КД/эффектами; собственные сообщения бота и сообщения безid пропускаются.

TLS6697, PING/PONG, RECONNECT, подтверждение JOIN, backoff1…30s. Лимиты100 каналов,
20JOIN/10s,20AUTH/10s. OAuth из окружения проверяется при запуске и каждый час.
Lease30s/renew10s ограничивает процесс; при потере запись эффектов запрещена.
Аварийный restart ждёт TTL прежнего lease. Сайт опрашивает статус каждые10s и после
reconnect; автоматической регистрации нет. Токены отсутствуют в DOM/preferences.

Запуск и точные примеры: [sudoku-v2-twitch.md](sudoku-v2-twitch.md).
Награды за баллы/EventSub — будущие адаптеры, сейчас реализованы команды чата.

## Проверка и ограничения

```powershell
$env:SUDOKU_V2_TEST_REDIS_URL = 'redis://127.0.0.1:6379/15'
.venv\Scripts\python.exe manage.py check --settings=tests.settings
.venv\Scripts\python.exe manage.py test tests --settings=tests.settings
node --test tests/js/sudoku_v2/*.test.mjs
```

Тесты используют SQLite, InMemoryChannelLayer и уникальные Redis-префиксы DB15.
Код тестов вынесен в корневой `tests/`; структура и отдельные команды —
в [tests/README.md](../tests/README.md).
Browser preview: localhost8765, отдельная SQLite `.tmp/sudoku-v2-preview.sqlite3`,
уникальный prefix `preview-sudoku-v2:<uuid>`, RedisChannelLayer с отдельным prefix.
Seed содержит шесть фиксированных уникальных задач; runtime-генерация проверяется
отдельно. Preview запрещает запуск настоящего Twitch worker.

Проверены генерация9/16, единственность, CAS-гонки/поколения, все шесть бонусов,
независимые таймеры, приватность, UI360/900/1440, fine/coarse pointer,
drag/resize/reset, reconnect, меню Twitch и fake IRC→Redis→Channels→браузер.
Подробные результаты и исправления каждого этапа:
[протокол Astra](superpowers/reviews/2026-10-11-sudoku-v2.md).
Финальный прогон11октября2026:108 Python с Redis без skips,53 Node,
Django check и diff --check PASS. Все11этапов прошли отдельное ревью Astra6;
найденные дефекты исправлены и перепроверены перед продолжением.

Live Twitch/OAuth, production-развёртывание, Firefox/Safari, физический телефон
и масштабный нагрузочный тест не выполнялись. Каталог ограничен9/16;
сложность считается по пустым клеткам, не по человеческим техникам решения.
При большом числе одновременных изменений ограниченные CAS-повторы могут
вернуть `board_busy`; отклонённый ход нужно повторить, настройки повторяются сами.
