# SudokuV2 Implementation Plan

> **For agentic workers:** Метод исполнения задан пользователем: основной агент
> реализует каждый этап, свежий субагент Astra 6 (`gpt-6-astra`) запускает проверки
> и проводит ревью по `find-bugs` перед следующим этапом. Steps use checkbox (`- [ ]`)
> syntax for tracking. Это заменяет стандартный выбор execution method навыка.

**Goal:** Выпустить SudokuV2 с досками 9×9/16×16, серверными бонусами, перемещаемыми
панелями и единым Twitch-ботом для нескольких комнат.

**Architecture:** Django/Channels/Redis сохраняют владение состоянием; сервер
атомарно фиксирует ход, бонус и состояние целей. Клиент хранит только раскладку
панелей и отображает серверные перестановки/эффекты. Отдельный процесс того же
проекта принимает чат Twitch и вызывает общий сервис без игрового суперпользователя.

**Tech Stack:** Python текущего venv; Django 5.0.0, Channels 4.1.0, channels-redis
4.2.0; существующий Redis; vanilla ES modules, node:test; GridStack 14.0.0;
asyncio TLS IRC; Django test runner и браузерный Playwright при наличии.

**Spec:** `docs/superpowers/specs/2026-10-11-sudoku-v2-design.md`.
До реализации прочитать целиком спецификацию и функциональный анализ
`docs/sudoku-v2-functional-analysis.md`.

## Global Constraints

- Название `SudokuV2`, приложение `sudoku_v2`, ветка `codex/sudoku-v2`.
- В этой поставке каталог размеров `[9, 16]`; B = isqrt(N), B² = N.
- Раскладка живёт только в памяти страницы, после reload сбрасывается.
- На телефоне функция перемещения не нужна.
- Бонус определяется бэком при первом правильном заполнении бонусной клетки.
- Параметры одного события едины для всех целей.
- SWAP меняет две строки или два столбца исключительно внутри одной группы B.
- Канонические индексы и решение не перемещаются в хранилище.
- Длительность устанавливает сервер, по умолчанию 30 секунд.
- Каждый эффект снимается собственным setTimeout; одинаковые эффекты независимы.
- КД по умолчанию 0; повторная регистрация обновляет только КД.
- Команды: `!<command> <name> <args>`; name по умолчанию `*`.
- Недопустимый параметр заменяется своим значением по умолчанию.
- Решение, чужой config, токены и локальные файлы не входят в публичные снимки.
- Конверт `{kind,data}`, поколения, ревизии, presence и текущая offline-семантика
  сохраняются; клиент не генерирует игровые случайные параметры.
- Не запускать production settings/миграции/заполнение настоящей БД в тестах.
- Не менять чужие незавершённые файлы и не редактировать desktop-репозиторий бота.

## Review Focus

1. Смешанные 9×9/16×16: одинаковые параметры должны подходить всем целям; старый
   game не должен случайно получить 256 клеток. Тесты этапов 2, 3, 5, 8.
2. Два правильных хода, повтор сообщения Twitch и CAS-конфликт: только одно
   потребление/событие, без частично изменённых целей. Тесты этапов 5 и 8.
3. Поздний снимок, новый generationId, скрытая вкладка, таймер первого из двух
   эффектов: нельзя воскресить старый эффект или снять соседний. Этап 6.
4. Перестановка/resize/смена размера во время ввода: канонический индекс, заметки,
   фокус и ожидающий ход сохраняют смысл. Этапы 4, 6, 7.
5. Повтор привязки, выход владельца, переоткрытая комната с тем же именем, restart
   worker: старый канал/пакет не попадает в другую комнату; КД не сбрасывается.
   Этапы 8–10.
