## Библиотеки

**Добавлена только GridStack 14.0.0** для drag/resize desktop-панелей, лицензия MIT.
JS/CSS лежат локально; runtime не зависит от CDN. Источник указан в
[vendor README](../sudoku_v2/static/sudoku_v2/vendor/gridstack/14.0.0/README.md).

Python requirements остались прежними: Django 5.0.0, daphne 4.1.2, channels 4.1.0,
channels-redis 4.2.0, requests 2.32.3, python-dotenv 1.0.1, django-redis 6.0.0.
Нового Twitch SDK нет: транспорт использует `asyncio`/`ssl`, проверка OAuth —
существующий `requests`. Для JS-тестов используется встроенный `node:test`.
Frontend framework, bundler и новые npm test dependencies не добавлялись.

## Оценка сложности и возможности упрощения

Astra считает большой diff трудным для одного ревью. Основная сложность —
транзакции нескольких досок и жизненный цикл Twitch: presence, generation,
bindingId, roomEpoch, dedup, КД и lease должны быть согласованы. В клиенте важны
порядок ответов, идентичность DOM, таймеры и корректная очистка подписок.

Рекомендации агента ниже **не реализованы этим переносом**:

- Развернуть плотные однострочные ветки и несколько действий на строке в IRC/worker,
  registry и UI. Строк может стать больше, но ревью станет проще.
- Удалить неиспользуемую обёртку `SudokuV2Service.valid_cell_index`; выигрыш небольшой.
- Выделить небольшие helpers повторной нормализации context и регистрации/снятия
  DOM listeners. Не превращать их в универсальный framework.
- Заменить заимствование методов других TestCase явными fixtures/support helpers.
  Перенос в `tests/` отделяет код, но сам по себе не устраняет эти связи.
- При дальнейшем развитии отделить Twitch API façade от игрового service.
  Это разделяет обязанности, но не гарантирует меньше строк.

Оснований обещать безопасное сокращение приложения вдвое агент не нашёл.
Не стоит убирать проверки гонок/дедупликации, реальные Redis-тесты, очистку
таймеров и проверку единственности генератора ради меньшего diff.

Практический порядок отдельных проходов ревью: rename/маршруты → размеры →
генератор → серверные бонусы/Redis → Twitch-команды/реестр → IRC/worker → клиент →
preview/эксплуатация. Соответствующие тесты читать вместе с каждым блоком.
