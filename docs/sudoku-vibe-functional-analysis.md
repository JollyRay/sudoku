# Sudoku Vibe: функциональный контракт и текущее состояние

Документ фиксирует функциональный ориентир старого Sudoku и фактический
контракт уже реализованного компонента `sudoku-vibe`. Особенности реализации
старого компонента не считаются контрактом новой версии.

## Маршруты и вход в лобби

- `GET /sudoku-vibe/` показывает форму с именем пользователя и названием
  комнаты.
- `POST /sudoku-vibe/` валидирует форму, сохраняет название комнаты и имя
  пользователя в сессии и перенаправляет на `/sudoku-vibe/lobby`. Имя хранится
  в `sudoku_vibe_username`, поэтому поддерживает кириллицу и другие Unicode-
  символы без передачи исходного текста в HTTP-cookie.
- Cookie для CSRF и сессии используют production-настройки по умолчанию, но
  могут быть настроены через `COOKIE_DOMAIN` и `COOKIE_SECURE`. В режиме
  `DEBUG` локальный HTTP-запуск не требует secure-cookie и домена
  `.schepka26.ru`.
- Пара «комната + имя пользователя» уникальна среди активных подключений.
  Форма выполняет предварительную проверку, а WebSocket атомарно захватывает
  имя при подключении.
- Страница `/sudoku-vibe/lobby` строит начальную доску с именем из сессии.
  Для существующих входов без `sudoku_vibe_username` форма, страница и
  WebSocket читают прежнюю cookie `nick`. Если имя отсутствует в обоих
  источниках, для доски используется строка `undefined`.
- Наличие комнаты окончательно проверяется при WebSocket-подключении. Без
  `room_code` в сессии соединение закрывается кодом `4401`.

## Игровые доски

- Доска имеет фиксированный размер 9×9 и 81 ячейку с индексами от `0` до
  `80`.
- У каждого активного пользователя есть собственная доска, названная его
  именем.
- Начальный HTML содержит одну пустую доску текущего пользователя. Доски
  остальных участников создаются клиентом динамически.
- При подключении нового игрока сервер отправляет его доску уже подключённым
  участникам.
- Запрос полного состояния возвращает сохранённые доски и пустые доски всех
  активных игроков. Поэтому новый игрок также видит уже подключённых
  участников, даже если они ещё не генерировали Sudoku.
- Повторное подключение восстанавливает сохранённые значения и список
  неизменяемых клеток.
- Отключение пока не удаляет HTML-доску у остальных клиентов и не удаляет
  сохранённое состояние доски из Redis.

Формат доски в сетевом протоколе:

```json
{
  "name": "player",
  "values": {"0": 5, "1": ""},
  "fixedCells": [0]
}
```

`values` содержит значения по индексам клеток. `fixedCells` содержит индексы
исходных значений сгенерированной задачи, которые нельзя менять.

## Генерация и изменение доски

- Клиент может запросить генерацию с полями `difficulty` и `size`.
- Сейчас поддерживается только размер `9`. Сложность передаётся как имя
  записи `game.Difficulty`.
- Сервер выбирает случайную подходящую запись `game.SudokuBoard` и получает
  её 81 клетку из `game.SudokuCell`.
- Клетки с `is_empty = false` записываются как исходные и неизменяемые.
- Замена значений доски и списка исходных клеток выполняется одной Redis-
  транзакцией. Частично сохранённая доска не должна становиться доступной.
- Пользователь может изменять только доску, имя которой совпадает с его
  серверным именем.
- Допустимы только значения из пользовательского конфига. Значения по
  умолчанию: пустая строка и целые числа от `0` до `9`.
- Сервер атомарно проверяет существование доски и отсутствие клетки в
  `fixedCells` вместе с записью нового значения.
- Клиент не меняет DOM оптимистично. Значение применяется только после
  успешного подтверждения сервера.
- Подтверждённое изменение получает автор, после чего оно рассылается всем
  остальным подключениям комнаты.

## Конфигурация клиента

Класс `SudokuConfig` хранит:

- текущий WebSocket;
- имя пользователя;
- доступные значения доски;
- список полей, которые разрешено отправлять серверу.

По умолчанию отправляются `username` и `allowedValues`. WebSocket не входит в
сериализуемый контекст. Сервер всегда заменяет присланное имя на имя,
полученное из сессии соединения (или прежней cookie `nick` для существующих
входов).

Конфигурация другого игрока, пришедшая вместе с рассылкой его доски, не
применяется к текущему клиенту.

## Библиотека работы с доской

Модуль `board.js` предоставляет операции:

- создать отсутствующую доску по имени;
- установить допустимое значение в клетку;
- отметить исходные неизменяемые клетки;
- поменять местами две строки;
- поменять местами два столбца.

Установка значения проверяет его по `config.allowedValues` и проверяет индекс
клетки. Если доски ещё нет в DOM, она создаётся до применения значения.

Все ES-модули загружаются с согласованной версией URL. Это не позволяет
браузеру совместить новый входной модуль со старой закэшированной версией его
зависимостей.

## Очередь событий

`EventQueue` получает имя события, задержку, признак цикличности и аргументы:

- обработчики находятся в общей карте `availableEvents`;
- одноразовое событие запускается через `setTimeout`;
- цикличное событие запускается через `setInterval`;
- неизвестное имя события отклоняется.

Дополнительное состояние или сложная модель очереди не хранятся.

## WebSocket-протокол

Адрес соединения: `/ws/sudoku-vibe/`.

Каждое сообщение имеет конверт:

```json
{"kind": "message_kind", "data": {}}
```

### Запросы клиента

| `kind` | `data` | Результат |
| --- | --- | --- |
| `get_board_data` | `{}` | Полное состояние своей доски, всех известных досок и своего конфига |
| `set_context` | поля конфига | Сохранение контекста пользователя без отдельного success-ответа |
| `generate_board` | `difficulty`, `size` | `board_data` автору и остальным участникам |
| `set_value` | `boardName`, `cellIndex`, `value` | `set_value` автору и остальным участникам |

### Сообщения сервера

| `kind` | Назначение |
| --- | --- |
| `board_data` | Полное состояние, сгенерированная доска или доска нового игрока |
| `set_value` | Подтверждённое изменение клетки |
| `bonus` | Запуск клиентского события по `name`, `args`, `delayMs`, `cyclic` |
| `error` | Ошибка с полями `code` и `message` |

Клиент уже умеет принимать `bonus`, но серверная бизнес-логика выдачи
бонусов пока не реализована.

## Серверные слои

- `SudokuVibeConsumer` отвечает за соединение, JSON-конверт, маршрутизацию,
  ответы и групповые рассылки.
- `SudokuVibeService` содержит правила Sudoku: владение доской, допустимые
  значения, генерацию и формирование состояния.
- `SudokuVibeStorage` изолирует ключи и операции Redis.
- `common.redis.RedisClient` предоставляет обычные и атомарные Redis-
  операции, необходимые хранилищу.

Таким образом, транспорт не содержит правил изменения игрового поля, а
бизнес-логика не управляет WebSocket напрямую.

## Redis и жизненный цикл подключения

Все ключи новой версии имеют префикс `sudoku-vibe:<room>` и не пересекаются с
регистрацией игроков старого Sudoku.

В Redis хранятся:

- контексты пользователей;
- имена созданных досок;
- значения клеток каждой доски;
- индексы исходных неизменяемых клеток;
- временные presence-lock активных пользователей.

Presence-lock содержит случайный `connection_id`, живёт 90 секунд и
продлевается каждые 30 секунд. Освободить или продлить lock может только его
владелец. Если процесс аварийно завершился, имя автоматически освободится
после TTL.

Перед обработкой сообщения lease проверяется и продлевается. Кроме того,
`connection_id` проверяется атомарно внутри каждой мутации Redis. Старое
соединение не может записать контекст, значение или новую доску после того,
как имя было захвачено другим соединением.

Коды закрытия:

- `4401` — в сессии нет комнаты;
- `4409` — имя занято или соединение было заменено;
- `1011` — presence не удалось проверить из-за внутренней ошибки.

## Ошибки бизнес-логики

Сервер может вернуть, среди прочих, следующие коды:

- `invalid_message`, `invalid_json` — неправильный конверт или JSON;
- `invalid_context` — недопустимый пользовательский конфиг;
- `invalid_board`, `board_not_found` — доску нельзя сгенерировать;
- `board_access_denied` — пользователь не владеет указанной доской;
- `invalid_value` — неправильный индекс или значение;
- `immutable_cell` — попытка изменить исходную клетку;
- `connection_replaced`, `presence_unavailable` — соединение больше не
  владеет пользовательским lease или его нельзя проверить.

## Функциональный ориентир следующих этапов

Старый Sudoku также предоставляет возможности, которые ещё не перенесены в
`sudoku-vibe`:

- выбор клетки и экранную цифровую панель;
- ввод с клавиатуры, режимы «сначала клетка» и «сначала цифра»;
- заметки-кандидаты и подсветку одинаковых значений;
- визуализацию ошибок;
- прогресс заполнения и таймер;
- проверку завершения и фиксацию результата;
- выбор доски соперника в оформленном UI;
- серверную выдачу бонусов и эффекты скрытия/вращения блоков;
- интеграцию Twitch;
- удаление или скрытие доски участника при выходе из лобби;
- полноценное визуальное оформление и адаптивный UI.

Эти пункты остаются функциональным ориентиром, но не являются описанием уже
готового поведения текущей версии.

## Архитектурные ограничения

В дальнейшей работе не следует возвращать:

- зависимость разметки от абсолютных координат и размеров;
- объединение DOM, сетевого протокола, бизнес-логики и эффектов в одном
  модуле;
- сообщения с полями вне конверта `{kind, data}`;
- оперативную регистрацию `sudoku-vibe` через SQL-модели старой игры;
- доверие к присланному клиентом владельцу доски, имени или признаку
  завершения;
- неатомарную запись доски отдельно от списка исходных клеток;
- изменение DOM до серверного подтверждения операции.
