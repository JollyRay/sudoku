# Twitch в SudokuV2

Один процесс читает чаты через исходящее TLS-подключение к
`irc.chat.twitch.tv:6697`, применяет команды через общий игровой сервис и
рассылает эффекты через Channels/Redis. Открывать дополнительный порт, выдавать
боту игровую доску или права суперпользователя не требуется. Веб-приложение и
worker должны использовать одинаковые Redis, prefix и channel layer.

## Запуск

Используется существующий **user OAuth** аккаунта бота с `chat:read`.
Login должен совпадать с владельцем токена. Токен принимается с префиксом
`oauth:` или без него. Токен задаёт оператор в окружении процесса; сайт его не
принимает и не показывает. Старый встроенный токен из desktop-бота не переносится.
Валидность определяется ответом [Twitch /validate](https://dev.twitch.tv/docs/authentication/validate-tokens/):
HTTP 200, совпадающий пользователь и `chat:read`. Значение `expires_in=0` само
по себе не отклоняет токен. При ошибке авторизации команда выводит причину и
завершается с ненулевым кодом; `Redis connection closed` означает закрытие клиента.

В PowerShell после безопасной загрузки окружения:

```powershell
.venv\Scripts\python.exe manage.py run_twitch_bot --settings=sudoku_v2.worker_settings
```

Нужны переменные `SUDOKU_V2_TWITCH_LOGIN` и `SUDOKU_V2_TWITCH_TOKEN`.
Не передавайте токен аргументом команды и не сохраняйте в репозитории.
Worker settings используют общие настройки Redis/Channels и подключают только
`sudoku_v2`. SQL-база и проверки URL сайта отключены; `game`, `voice` и другие
приложения сайта не загружаются, поэтому их startup-очистка не запускается.
**Указывайте эти settings сразу при запуске Django.** Проверка внутри команды
не может отменить уже выполненный startup hook при ошибочном выборе settings.
Preview settings запрещают запуск бота до чтения токена/сетевых вызовов.

Для `fillSudoku` используются отдельные `sudoku_v2.generator_settings`: база
проекта и модели `game` без его `ready()`. Команда генерации в worker недоступна.

Пример Linux service: [sudoku-v2-twitch.service.example](../config/sudoku-v2-twitch.service.example).
Замените пути/user; отдельный `/etc/sudoku/twitch.env` с правами600 содержит
две переменные окружения. Сервис автоматически не устанавливается.
При недействительном токене процесс останавливается с `auth_error`;
оператор обновляет окружение и перезапускает его. Автоматического refresh нет.
После сетевой ошибки IRC восстанавливается с задержкой1…30s. Ошибка часовой
проверки OAuth останавливает transport; systemd может перезапустить worker.

## Подключение на сайте

Игрок указывает login канала (без URL и `#`) и КД в секундах0…86400, default0.
Канал закрепляется за одним лобби и подключившим его игроком. Повторное
подключение тем же игроком меняет только КД. Изменить/отключить связь может
только её владелец. Команды пропускаются, когда владелец отсутствует; связь
остаётся, пока в лобби есть игроки. Последний выход удаляет связь.

Статусы: `disabled` — worker остановлен/не доступен, `connecting` — ожидается
подключение/лимит, `connected` — Twitch подтвердил JOIN, `auth_error` — нужен
новый OAuth, `error` — проблема сети/канала/лимит100 каналов. Если JOIN не
подтверждён за15s, выдаётся `join_timeout` без повторного спама. Проверьте login;
для новой попытки отключите и подключите канал. Одна и та же привязка при
изменении КД не отправляет новый JOIN. Смена владельца/поколения привязки
перезапускает IRC stream, чтобы старые подтверждения не меняли новую связь.

## Команды

`!command name args`, default name=`*` — все текущие игроки с незавершённой доской,
включая подключившего бота. Его также можно выбрать явно по имени; команды работают
и когда он играет один. Имена с пробелами заключаются в двойные кавычки. Неизвестное имя
также означает `*`; невалидные параметры заменяются серверными defaults.
Лишние параметры игнорируются. Команды доступны всем зрителям.

| Команда | Пример | Эффект |
| --- | --- | --- |
| swap | `!swap * col 1 2` | Обмен допустимых столбцов/строк внутри группы |
| blur / shadow | `!blur "Игрок 2" 3` | Размытие блока3 |
| rotate / roll | `!rotate` | Вращение случайного блока |
| dance | `!dance * 1` | Танцующие клетки блока1 со сменой цветов |

Нумерация в чате начинается с1. Без name, но с args пишите `*`. Продолжительность
и интенсивность задаются сервером, default30s для временных эффектов. Параметры
общие для всех целей9×9/16×16. Свою доску владелец командой не атакует.

КД общий для канала, расходуется только успешным эффектом. При КД0 нет
пользовательского ограничения частоты. Одинаковый message-id принимается один
раз за24h, даже после переподключения; сообщения безid и собственные сообщения
бота игнорируются. Эффекты, КД и дедупликация фиксируются атомарно. Ответов в чат нет.

## Эксплуатация и расширение

Сверка реестра каждые2s. Один worker на bot-id защищён lease30s с обновлением10s;
потеря lease запрещает commit эффекта даже до остановки транспорта.
После аварии новый worker ждёт истечения прежнего lease и восстанавливает связи.
Статус подключения обновляется вместе со сверкой и истекает через45s при аварии процесса.
OAuth проверяется при запуске и каждый час. Настройки worker:
`TWITCH_MAX_CHANNELS=100`, `TWITCH_JOIN_LIMIT=20`, `TWITCH_AUTH_LIMIT=20`
(последние два — за10s). Не запускайте старый desktop-бот одновременно с новым:
ограничения Twitch общие для аккаунта.

Будущие EventSub/rewards-адаптеры могут создавать `ExternalBonusCommand` и
передавать запросы через общий BonusService с guards. Текущий TwitchService
принимает только `source=twitch_chat`; поддержку наград и их авторизацию
нужно добавить отдельно. Реальная подписка на награды здесь не создаётся.

Проверки этой поставки используют fake IRC/OAuth и локальный Redis.
Live Twitch не проверен; после настройки оператору нужен контрольный чат:
подключить канал, дождаться `connected`, применить команду, проверить КД и
disconnect. Токен не следует присылать в чат или отчёт.

Источники: [IRC](https://dev.twitch.tv/docs/chat/irc/),
[лимиты Twitch](https://dev.twitch.tv/docs/chat/#rate-limits),
[OAuth validate](https://dev.twitch.tv/docs/authentication/validate-tokens/).
